# منصة شهداء ومفقودي حرب سوريا — الإصدار الثاني

## ما الجديد في هذا الإصدار

- **تسجيل بالبريد الإلكتروني:** إنشاء حساب، ثم تأكيد البريد برمز من 6 أرقام يصلك، ثم تسجيل الحالات. كل حساب يُربط بحالاته، ومن لا يملك بريداً صالحاً لا يستطيع التسجيل.
- **منع التكرار الحقيقي:** الاسم الواحد مرة واحدة لكل حساب في كل فئة، وتنبيه عند وجود أسماء متشابهة معتمدة.
- **لوحة إشراف كاملة:** اعتماد وأرفض وتعديل وحذف وإعادة للمراجعة، ودمج المكررات، وإيقاف الحسابات المسيئة، وتعيين مشرفين.
- **مربع ترحيب قابل للكتابة من المشرف** يظهر أعلى الصفحة الرئيسية ويشرح المنصة وطريقة التسجيل.
- **ملف شخصي قابل للتعديل:** الاسم، والنبذة، والصورة الشخصية، والشعار، ولغة الواجهة، وتغيير كلمة المرور.
- **تصدير CSV** للعامة (بالنتائج المفلترة) وللمشرفين (مع وسيلة التواصل والبريد)، بالعربية أو الإنجليزية، ويعمل مع ملايين السجلات بالتصدير على دفعات. الملف يحتوي على BOM ليُفتح بالعربية في Excel.
- **واجهة ثنائية اللغة** (عربي وإنجليزي) مع تبديل فوري، وتُحفظ اللغة في الحساب.

## التشغيل المحلي

1. Node.js 20.6 أو أحدث.
2. انسخ `.env.example` إلى `.env` وعدّل القيم، وأهمها `DATABASE_URL` و`ADMIN_EMAIL`.
3. شغّل:
   ```bash
   npm install
   npm run dev
   ```
4. في التطوير، إن لم تضبط SMTP تُطبع رموز التحقق في الطرفية بدلاً من إرسالها.

## إعداد البريد الإلكتروني

الرموز تُرسل عبر SMTP. خيارات مجانية أو شبه مجانية:
- **Brevo** أو **Resend** أو **Mailjet** (لها خطط مجانية، ويعطونك بيانات SMTP).
- **Gmail** بكلمة مرور تطبيق، مناسب للتجربة فقط وله حد يومي.

ضع البيانات في `SMTP_HOST` و`SMTP_PORT` و`SMTP_USER` و`SMTP_PASS` و`MAIL_FROM`. في الإنتاج لن يعمل التسجيل دون بريد مُهيأ، وهذا مقصود.

## أول تشغيل ومنح صلاحية الإشراف

ضع بريدك في `ADMIN_EMAIL` ثم أنشئ حساباً بهذا البريد وأكّده. يُمنح صلاحية الإشراف تلقائياً. بعدها يمكنك منح الإشراف لآخرين من تبويب "المستخدمون".

## النشر المجاني

- **قاعدة البيانات:** Neon أو Supabase (PostgreSQL مجاني). انسخ رابط الاتصال إلى `DATABASE_URL`.
- **الخادم:** Render أو أي خدمة تدعم Node.js. Build: `npm install`، Start: `npm start`، وأضف متغيرات البيئة من لوحة الخدمة.

**هام:** هذا الإصدار يستخدم جداول جديدة. إن كان لديك الإصدار الأول على قاعدة بيانات، استخدم قاعدة جديدة لهذا الإصدار.

## الخصوصية والأمان

- كلمات المرور مُجزّأة بـ scrypt، والجلسات مخزّنة مُجزّأة، وملف تعريف الارتباط HttpOnly.
- رموز التحقق صالحة 15 دقيقة، ومحاولاتها محدودة بخمس.
- وسيلة التواصل والبريد الإلكتروني لا يظهران إلا للمشرفين في لوحة الإشراف والتصدير الإداري.
- ملفات CSV تُحمى من حقن المعادلات في Excel.

## إعداد Cloudflare R2 لتخزين الصور

1. أنشئ حساب Cloudflare، ثم من القائمة اختر **R2 Object Storage** وفعّله بالخطة المجانية.
2. أنشئ **Bucket** باسم مثل `syria-martyrs-images`.
3. من إعدادات الـ Bucket فعّل **Public access** لتحصل على رابط `r2.dev`، أو اربط نطاقاً مخصصاً.
4. من **Manage R2 API Tokens** أنشئ توكن بصلاحية **Object Read & Write** على هذا الـ Bucket، واحفظ مفتاح الوصول والمفتاح السري.
5. ضع القيم في `.env` أو في لوحة الخدمة: `R2_ACCOUNT_ID` (يظهر في صفحة R2)، و`R2_ACCESS_KEY_ID`، و`R2_SECRET_ACCESS_KEY`، و`R2_BUCKET`، و`R2_PUBLIC_URL`.

يُرفع كل صورة بعد تصغيرها إلى مجلدات `records/` و`avatars/` و`logos/`، وتُخزَّن في قاعدة البيانات أو في الملف الشخصي رابطها فقط. تُحذف الصورة من R2 عند حذف السجل أو استبدال الصورة. في الإنتاج يرفض الخادم العمل دون R2.

## حدود معروفة

1. **رسائل الخادم بالعربية:** عناصر الواجهة مترجمة، أما رسائل الأخطاء القادمة من الخادم فما تزال بالعربية. إضافتها للإنجليزية تحتاج تحويل الأخطاء إلى رموز.
2. **ترجمة المحتوى:** الأسماء والملاحظات تُعرض كما كُتبت، والمحافظات تُترجم في ملفات CSV فقط.
3. **الصور في قاعدة البيانات:** الخطة المجانية غالباً نحو 0.5 غيغابايت، والصور تستهلك المساحة بسرعة. عند الوصول للحد انقل الصور إلى خدمة ملفات مثل Cloudflare R2 أو Supabase Storage.
4. **تغيير البريد الإلكتروني:** غير متاح من الملف الشخصي بعد، ويمكن إضافته بالطريقة نفسها التي يعمل بها رمز التحقق.
5. **كشف التكرار:** يعمل بالمقارنة الكاملة بين المعتمدة، ومع مليوني سجل يُنصح بتشغيله كمهمة دورية بدل الاستعلام الحي.
6. **النسخ الاحتياطي:** فعّله من لوحة مزود قاعدة البيانات.
7. **تنظيف الجلسات المنتهية:** لا يحدث تلقائياً بعد، ويمكن إضافته كمهمة دورية بسيطة.
